# 内容质量要求

> 本文档定义了文章内容的质量标准和检查要求

## 核心质量原则

### 1. 准确性
- **技术准确**: 所有技术内容必须准确无误
- **版本一致**: 针对仓颉1.0.5 LTS版本
- **官方参考**: 严格基于官方文档
- **可验证**: 所有代码示例必须可运行

### 2. 深度
- **概念深入**: 深入解释语言概念，不浮于表面
- **原理分析**: 适当讲解底层原理
- **最佳实践**: 提供实际开发建议
- **常见陷阱**: 指出容易出错的地方

### 3. 实用性
- **代码可用**: 提供完整可运行的代码示例
- **场景真实**: 基于真实开发场景
- **问题解决**: 解决实际开发问题
- **迁移帮助**: 帮助从其他语言迁移

### 4. 原创性
- **独立思考**: 有独立的见解和分析
- **深度加工**: 对官方内容进行深度加工
- **独特视角**: 提供独特的视角和见解
- **价值增加**: 比官方文档提供更多价值

## 内容结构要求

### 文章结构
```
1. 标题
2. 摘要/导读
3. 背景介绍
4. 核心内容
   - 概念解释
   - 语法说明
   - 代码示例
   - 最佳实践
5. 语言对比（如适用）
6. 总结
7. 参考资料
8. 版权声明
```

### 章节要求
- **逻辑清晰**: 章节之间逻辑连贯
- **层次分明**: 使用合适的标题层级
- **重点突出**: 重要内容有明显标识
- **过渡自然**: 章节之间过渡自然

## 知识点要求

- **背景说明**: 解释概念的背景和用途

### 语法说明
- **完整语法**: 提供完整的语法格式
- **参数说明**: 详细说明每个参数
- **返回值**: 说明返回值类型和含义
- **异常处理**: 说明可能的异常情况

### 代码示例
- **完整代码**: 提供完整的代码示例
- **可运行性**: 代码必须能够直接运行
- **注释详细**: 关键代码有详细注释

### 最佳实践
- **命名规范**: 遵循语言命名约定

## 语言对比要求

### 对比维度
1. **语法对比**: 语法结构的异同
2. **特性对比**: 语言特性的差异
3. **性能对比**: 性能特点的差异
4. **生态对比**: 生态系统的差异
5. **适用场景**: 不同场景的适用性

### 对比深度
- **深入分析**: 深入分析异同点
- **原因解释**: 解释差异的原因
- **影响分析**: 分析差异的影响
- **迁移建议**: 提供迁移建议

### 对比语言
- **Golang**: 并发模型、类型系统、包管理
- **Java**: 面向对象、泛型、异常处理
- **Swift**: 协议、泛型、内存管理
- **Kotlin**: 协程、扩展函数、空安全

## 代码质量要求

### 代码规范
- **命名规范**: 遵循仓颉命名约定
  - 变量名: camelCase
  - 函数名: camelCase
  - 类名: PascalCase
  - 常量: UPPER_SNAKE_CASE
- **代码风格**: 一致的代码风格
- **缩进格式**: 使用4个空格缩进
- **行长度**: 建议不超过80字符

### 代码完整性
- **导入语句**: 包含必要的导入语句
- **上下文完整**: 提供完整的上下文
- **错误处理**: 包含适当的错误处理
- **资源清理**: 必要时进行资源清理

### 代码注释
- **关键注释**: 关键代码必须有注释
- **解释原理**: 解释代码的原理和目的
- **参数说明**: 说明参数的含义和用法
- **返回值说明**: 说明返回值的含义

### 代码验证
- **编译通过**: 代码必须能够编译通过
- **运行正确**: 代码运行结果必须正确
- **边界测试**: 测试边界情况
- **错误处理**: 测试错误处理
