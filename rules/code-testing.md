# 代码测试规范

> 本文档定义了代码示例的测试要求和流程

## 测试目标

### 核心目标
- **正确性**: 确保代码示例能够正确编译和运行
- **可靠性**: 确保代码示例在不同环境中都能正常工作
- **可维护性**: 确保代码示例易于理解和维护

### 具体目标
1. 所有代码示例必须通过本地测试
2. 所有代码示例必须通过GitHub Actions测试
3. 所有代码示例必须有明确的预期输出
4. 所有代码示例必须符合语言规范

## 测试要求

### 强制要求

#### 1. 本地测试
- **要求**: 所有代码示例必须在本地测试通过
- **工具**: `./tools/test-local.sh`
- **时机**: 提交前必须测试
- **标准**: 所有测试必须通过

#### 2. GitHub Actions测试
- **要求**: 所有代码示例必须通过GitHub Actions测试
- **触发**: 推送到main或draft分支时自动触发
- **标准**: 所有测试必须通过
- **报告**: 生成测试报告

#### 3. 代码示例规范
- **完整性**: 代码示例必须完整，不依赖外部文件
- **可运行性**: 代码示例必须能够编译和运行
- **预期输出**: 代码示例必须有明确的预期输出
- **注释**: 关键代码必须有详细注释

### 推荐要求

#### 1. 多语言测试
- **要求**: 涉及多语言对比的文章，所有语言的代码示例都必须测试
- **支持语言**: 仓颉、Java、Golang、Kotlin、Swift、Rust、C++、Zig、Python
- **测试方式**: 使用本地测试脚本或GitHub Actions

#### 2. 边界测试
- **要求**: 测试边界情况和异常情况
- **示例**: 空输入、最大值、最小值等
- **目的**: 确保代码示例的健壮性

#### 3. 性能测试
- **要求**: 涉及性能优化的代码示例，需要进行性能测试
- **指标**: 执行时间、内存使用等
- **目的**: 验证性能优化效果

## 测试流程

### 文章创作流程中的测试

#### 1. 内容研究阶段
- **任务**: 准备代码示例
- **要求**: 确保代码示例的准确性
- **验证**: 查阅官方文档，验证语法正确性

#### 2. 代码验证阶段
- **任务**: 在本地测试代码示例
- **工具**: 语言特定的编译器和运行时
- **要求**: 代码必须能够编译和运行

#### 3. 初稿撰写阶段
- **任务**: 将代码示例集成到文章中
- **要求**: 使用正确的Markdown代码块语法
- **格式**: ````language` 格式

#### 4. 本地测试阶段
- **任务**: 运行本地测试脚本
- **命令**: `./tools/test-local.sh`
- **要求**: 所有测试必须通过
- **修复**: 修复所有测试失败的示例

#### 5. 审核优化阶段
- **任务**: 用户审核文章
- **要求**: 根据反馈修改代码示例
- **验证**: 修改后重新测试

#### 6. 最终确认阶段
- **任务**: 确认文章质量
- **要求**: 所有代码示例必须通过测试
- **标准**: 本地测试和GitHub Actions测试都通过

#### 7. 版本提交阶段
- **任务**: 提交代码到Git
- **要求**: 提交前必须测试通过
- **验证**: 确认测试报告

#### 8. 发布准备阶段
- **任务**: 准备发布文章
- **要求**: 确认GitHub Actions测试通过
- **检查**: 查看GitHub Actions运行结果

## 测试工具

### 1. 本地测试脚本

**文件**: `tools/test-local.sh`

**功能**:
- 自动提取所有文章中的代码示例
- 测试所有支持的语言
- 生成测试报告

**使用方法**:
```bash
# 运行所有测试
./tools/test-local.sh

# 查看测试报告
cat test_output/test_report.md
```

### 2. GitHub Actions工作流

**文件**: `.github/workflows/code-examples-test.yml`

**功能**:
- 自动测试所有代码示例
- 支持多种编程语言
- 生成测试报告

**触发条件**:
- 推送到main或draft分支
- 创建Pull Request
- 手动触发

**查看结果**:
- GitHub仓库的Actions页面
- 测试报告Artifact

### 3. 代码提取脚本

**文件**: `.github/scripts/extract_code.py`

**功能**:
- 从Markdown文章中提取指定语言的代码块
- 保存为可执行文件

**使用方法**:
```bash
# 提取仓颉代码
python3 .github/scripts/extract_code.py --lang cangjie --output test_output/cangjie/

# 提取Java代码
python3 .github/scripts/extract_code.py --lang java --output test_output/java/
```

## 测试标准

### 通过标准

#### 1. 编译通过
- 代码必须能够编译成功
- 没有编译错误
- 没有严重的编译警告

#### 2. 运行通过
- 代码必须能够运行成功
- 没有运行时错误
- 没有程序崩溃

#### 3. 输出正确
- 程序输出必须符合预期
- 没有意外的错误输出
- 输出格式正确

#### 4. 测试覆盖
- 所有代码示例都必须测试
- 没有遗漏的代码示例
- 测试覆盖率100%

### 失败标准

#### 1. 编译失败
- 代码无法编译
- 存在编译错误
- 存在严重的编译警告

#### 2. 运行失败
- 代码无法运行
- 存在运行时错误
- 程序崩溃

#### 3. 输出错误
- 程序输出不符合预期
- 存在意外的错误输出
- 输出格式错误

#### 4. 测试遗漏
- 存在未测试的代码示例
- 测试覆盖率不足
- 测试报告不完整

- **位置**: `test_output/test_report.md`
- **用途**: 本地测试结果记录
- **查看**: 直接查看文件

#### 2. GitHub Actions报告
- **位置**: GitHub Actions Artifact
- **用途**: 远程测试结果记录
- **查看**: 在Actions页面下载Artifact

## 故障排除

### 常见问题

#### 1. 仓颉编译器未找到

**问题**: `cjc: command not found`

**解决方案**:
```bash
# 检查仓颉SDK是否安装
cjc --version

# 如果未安装，下载并安装仓颉SDK
wget https://cangjie-lang.cn/download/1.0.5/cangjie-1.0.5-linux-x64.tar.gz
tar -xzf cangjie-1.0.5-linux-x64.tar.gz
export PATH=$PATH:/path/to/cangjie/bin
```

#### 2. 代码示例提取失败

**问题**: 没有提取到任何代码示例

**解决方案**:
- 检查Markdown文件中的代码块格式是否正确
- 确认代码块语言标识是否正确
- 查看extract_code.py的日志输出

#### 3. 编译错误

**问题**: 代码示例编译失败

**解决方案**:
- 检查代码语法是否正确
- 确认使用的语言版本是否正确
- 查看编译错误信息并修复

#### 4. GitHub Actions测试失败

**问题**: GitHub Actions测试失败

**解决方案**:
- 查看GitHub Actions运行日志
- 检查代码示例是否正确
- 修复失败的测试
- 重新推送代码
