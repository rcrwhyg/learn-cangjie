# 仓颉开发环境搭建与 Hello World

> **摘要**: 本文将以仓颉 1.0.5 LTS 为基础，介绍如何选择并安装 SDK、配置命令行环境、验证 `cjc` 和 `cjpm`，以及编写并运行第一个仓颉程序。完成本文后，你将拥有一个可以持续练习后续示例的本地开发环境。

## 前置知识

- 了解基本的命令行操作
- 能够在自己的操作系统上安装软件并修改环境变量
- 已阅读《仓颉编程语言简介与特性概览》

## 1. 先明确需要安装什么

### 1.1 SDK 包含哪些工具

学习仓颉不需要分别安装编译器和包管理器。仓颉 SDK 通常包含以下开发工具：

| 工具 | 作用 |
|------|------|
| `cjc` | 仓颉编译器，将 `.cj` 源文件编译为可执行文件或其他编译产物 |
| `cjpm` | 仓颉项目管理工具，用于初始化、构建和运行项目 |
| 标准库 | 提供语言运行所需的基础类型和 API |
| 编辑器插件 | 为 VS Code 等编辑器提供语法高亮、补全和诊断能力 |

本文统一以仓颉 **1.0.5 LTS** 为准。不要把不同版本的编译器、标准库和文档混用，否则可能出现语法或 API 不一致的问题。

### 1.2 选择适合自己的开发方式

你可以选择以下任一种方式：

- **命令行 + 任意编辑器**：依赖最少，最适合学习编译流程和排查环境问题。
- **VS Code + 仓颉插件**：提供语法高亮、代码补全和错误提示，适合日常写作。
- **华为开发者空间或 CodeArts IDE**：不想在本地配置 SDK 时，可以使用官方提供的云端或集成开发环境。

无论使用哪种编辑器，真正负责编译和运行的仍然是 SDK 中的工具。因此，本文先完成命令行验证，再配置编辑器。

## 2. 下载并安装仓颉 SDK

### 2.1 从官方下载中心获取 SDK

打开仓颉官方下载中心，在 LTS 版本中选择 **1.0.5**，再根据操作系统和 CPU 架构选择对应安装包：

https://cangjie-lang.cn/download

下载时注意以下事项：

1. 不要误选 STS 或 Nightly Builds 版本。
2. Linux、Windows 和 macOS 的安装包不能混用。
3. Apple Silicon 和 Intel Mac 应确认 SDK 是否匹配当前架构。
4. 如果项目要求固定版本，应记录下载的版本和平台，避免团队成员使用不同 SDK。

### 2.2 配置命令行路径

安装或解压 SDK 后，需要将 SDK 的 `bin` 目录加入 `PATH`。下面的路径只是示例，请替换为自己的实际路径。

在 Linux 或 macOS 的当前终端中执行：

```bash
export PATH="/path/to/cangjie/bin:$PATH"
```

如果希望每次打开终端都生效，可以把这行加入 shell 配置文件，例如 `~/.zshrc` 或 `~/.bashrc`，然后重新打开终端或执行对应的配置文件。

Windows 用户可以在“系统环境变量”或“用户环境变量”的 `Path` 中添加 SDK 的 `bin` 目录。修改后要重新打开 PowerShell 或命令提示符。

> **注意**: 如果电脑上已经安装过其他版本的仓颉，请检查 `PATH` 中是否同时存在多个 SDK 的 `bin` 目录。命令行通常会优先使用排在前面的版本。

## 3. 验证安装结果

打开一个新的终端，分别执行：

```bash
cjc --version
cjpm --version
```

确认输出能够识别到仓颉工具，并检查版本是否为 1.0.5。若终端提示找不到命令，优先检查以下内容：

- SDK 是否已经正确解压或安装。
- `bin` 目录是否加入了当前用户实际使用的 `PATH`。
- 修改环境变量后是否重新打开了终端。
- 当前终端找到的是否是另一套旧 SDK。

在 Linux 或 macOS 上，可以使用以下命令查看实际命中的路径：

```bash
which cjc
which cjpm
```

PowerShell 可以使用：

```powershell
Get-Command cjc
Get-Command cjpm
```

## 4. 编写第一个仓颉程序

在任意工作目录中创建 `hello.cj`。

<!-- example: cangjie/006-hello-world.cj -->
```cangjie
// Hello World 示例
main() {
    println("Hello, Cangjie!")
}
```

这个程序包含两个部分：

- `main()` 是程序入口，程序从这里开始执行。
- `println(...)` 将字符串输出到终端，并在末尾换行。

## 5. 使用编译器构建并运行

在 `hello.cj` 所在目录执行：

```bash
cjc hello.cj -o hello
```

编译成功后，Linux 和 macOS 通常可以这样运行：

```bash
./hello
```

Windows 用户运行编译生成的 `hello.exe`：

```powershell
.\hello.exe
```

预期输出为：

```text
Hello, Cangjie!
```

这里的流程可以拆成三步：

1. `cjc` 启动仓颉编译器。
2. `hello.cj` 是输入源文件。
3. `-o hello` 指定输出文件名。

直接使用 `cjc` 编译单个文件适合学习语法和验证小示例。随着项目变大，应使用 `cjpm` 管理项目结构和依赖。

## 6. 使用 cjpm 管理项目

### 6.1 初始化项目

在一个新的空目录中执行：

```bash
mkdir hello-cangjie
cd hello-cangjie
cjpm init
```

`cjpm init` 会创建项目所需的基础文件。不同 SDK 版本生成的配置内容可能略有差异，应以当前 SDK 生成的文件和 1.0.5 LTS 文档为准，不要直接复制其他版本的配置。

### 6.2 构建和运行项目

在项目目录中执行：

```bash
cjpm build
cjpm run
```

一般来说：

- `cjpm build` 用于检查项目是否能够构建。
- `cjpm run` 用于构建并运行项目。

如果命令提示缺少入口文件或配置项，先查看 `cjpm init` 生成的项目结构，再把 Hello World 代码放到项目要求的源文件位置。不要假设所有版本的默认目录完全相同。

## 7. 配置编辑器

### 7.1 VS Code

仓颉官方下载中心提供 VS Code 插件入口。安装插件后，建议重新打开项目目录，并确认编辑器使用的 SDK 与终端中的 `cjc --version` 是同一版本。

### 7.2 编辑器配置的基本原则

- 先保证命令行可以编译，再排查编辑器问题。
- 编辑器报告错误但命令行正常时，优先检查插件配置的 SDK 路径。
- 终端和编辑器可能使用不同的环境变量，不能只根据其中一方判断安装是否成功。

## 8. 常见问题

### Q1: `cjc: command not found` 怎么办？

确认 SDK 的 `bin` 目录已经加入 `PATH`，并重新打开终端。然后使用 `which cjc` 或 `Get-Command cjc` 检查命令解析结果。

### Q2: 编译成功但运行时失败怎么办？

先确认编译器版本和运行环境匹配，再检查系统架构和 SDK 的运行时库。macOS 上如果遇到 SDK 原生运行时与当前系统 SDK 的链接问题，可以先使用 Linux CI 完成完整编译运行验证；本项目的 macOS 测试会执行静态库编译检查。

### Q3: `cjpm` 找不到怎么办？

`cjpm` 通常和 `cjc` 一起位于 SDK 的 `bin` 目录。确认 `which cjc` 和 `which cjpm` 是否指向同一套 SDK。

### Q4: 为什么不直接使用最新版？

本系列内容编写时，最新长期维护版本为 1.0.5 LTS，所以以 1.0.5 LTS 为基准。最新版可能包含不同的语法、工具链行为或 API，如果后续官方发布新的长期支持版本，可能会在后续文章中说明并使用新版本。学习时应优先保证文章、SDK 和代码示例版本一致。

## 9. 总结

### 核心要点

1. 从官方下载中心获取与系统匹配的仓颉 1.0.5 LTS SDK。
2. 将 SDK 的 `bin` 目录加入 `PATH`。
3. 使用 `cjc --version` 和 `cjpm --version` 验证工具链。
4. 使用 `cjc` 编译单文件程序，使用 `cjpm` 管理项目。
5. 先验证命令行环境，再配置编辑器插件。

### 练习题

1. 修改 Hello World 程序，让它输出你的名字。
2. 分别使用 `cjc` 和 `cjpm` 构建一次 Hello World 程序。
3. 执行 `which cjc` 或 `Get-Command cjc`，记录当前使用的 SDK 路径。
